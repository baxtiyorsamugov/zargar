# Как мы работаем

## Процесс

1. **Всё начинается с Issue.** Задача, баг или вопрос для ADR — по шаблону.
2. Issue привязывается к **Milestone** — это этап дорожной карты (см. ниже) — и ставится на доску **Project** в колонку `Backlog`.
3. Берём задачу → колонка `In Progress`, создаём ветку.
4. Открываем Pull Request в `dev` → колонка `Review`.
5. После ревью и зелёного CI — merge → `Done`.
6. Релиз: PR `dev` → `main`, тег версии, запись в `CHANGELOG.md`.

### Доска (GitHub Projects)

`Backlog` → `To Do` → `In Progress` → `Review` → `Done`

### Milestones = этапы дорожной карты

| # | Этап |
|---|---|
| 01 | Старт и сбор материалов |
| 02 | UI/UX дизайн |
| 03 | Разработка (каталог, фильтры, поиск, ЛК, админка) |
| 04 | Интеграция с 1С |
| 05 | Bitrix CRM |
| 06 | Оплата и уведомления |
| 07 | Тест и запуск (SEO, скорость, домен) |
| 08 | Поддержка |

Названия совпадают с [дорожной картой](docs/client/SOFIZAR_Дорожная_карта.pdf).

### Метки (labels)

| Метка | Значение |
|---|---|
| `task` / `bug` / `adr` | Тип |
| `backend` `frontend` `infra` | Часть системы |
| `1c` `bitrix` `uzqr` | Интеграция |
| `seo` `docs` | Направление |
| `priority:high` | Делать в первую очередь |
| `blocked` | Ждём заказчика или внешнюю сторону |

## Ветки

| Ветка | Назначение |
|---|---|
| `main` | Продакшен. Только через PR из `dev`. Защищена. |
| `dev` | Интеграционная ветка, деплоится на staging. |
| `feat/<issue>-<кратко>` | Новая функциональность: `feat/12-product-filters` |
| `fix/<issue>-<кратко>` | Исправление бага |
| `docs/…`, `chore/…` | Документация, инфраструктура |

## Коммиты — Conventional Commits

```
<тип>(<область>): <что сделано>
```

Типы: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `ci`, `perf`, `style`.
Примеры:

```
feat(catalog): фильтр по пробе и цвету металла
fix(orders): двойное списание остатка при повторном webhook
docs(adr): ADR-0009 формат обмена с 1С
```

## Definition of Done

Задача готова, когда:

- код в `dev`, CI зелёный;
- есть тесты на новую логику;
- критерии приёмки из Issue выполнены и проверены;
- пользовательские тексты есть на UZ / RU / EN (или заведена задача);
- документация обновлена: API — в LLD, архитектурные решения — в ADR;
- запись в `CHANGELOG.md`;
- нет секретов в коде, конфигурация — через переменные окружения.

## Код

- **Python:** `ruff check` и `ruff format`. Тесты — `pytest`.
- **TypeScript:** `npm run lint`, `npm run typecheck`.
- Перед PR прогоните проверки локально (команды — в [README](README.md)).
