# api-sync — каталог сайта из 1С (Billing)

Скрипт забирает данные из API 1С (документ «SOFIZAR — API для получения данных из 1С», v1.2)
и собирает один файл каталога для сайта: `frontend/data/catalog.json` (и `catalog.js` для подключения тегом `<script>`),
фотографии — в `frontend/data/img/<item_id>.jpg`.

Почему так, а не запросы из браузера: API требует Basic-логин и токен и открыт только для одного статического IP.
Ключи нельзя отдавать в браузер, поэтому к 1С ходит только сервер, а сайт читает готовый файл.

Нужен Node.js 20+ (без npm-зависимостей).

## Настройка

1. Скопировать `.env.example` в `.env` и вписать адреса и доступы. `.env` в git не коммитится.
2. Проверка доступа: `node probe.mjs` (Windows: `probe.bat`). Сырые ответы и `REPORT.md` — в `Sofizar/api-samples/`.
   В отчёте видно, какие поля пришли, каких нет по документу, и что вернул каждый endpoint.
3. Выгрузка: `node sync.mjs` (Windows: `sync.bat`).

## Без Node.js (Windows)

1. `fetch.bat` — скачивает все страницы API через `curl.exe` в `Sofizar/api-samples/raw/` и первые 60 фото товаров в наличии в `frontend/data/img/` (параметр `-Images N`).
2. `node sync.mjs --from ../../api-samples/raw` — собирает `catalog.json` из скачанного. Нужен Node; можно запустить на любой машине, где он есть.
3. `probe.bat` — быстрая проверка доступности: коды ответов в `api-samples/curl-log.txt`.

## Команды

| Команда | Что делает |
|---|---|
| `node sync.mjs` | Полная выгрузка: health → categories, sets, products, prices, stock → catalog.json, фото |
| `node sync.mjs --no-images` | Без фото |
| `node sync.mjs --from <папка>` | Сборка из страниц, скачанных `fetch.bat` |
| `node sync.mjs --mock` | На тестовых данных из `fixtures/`, без сети (для вёрстки) |
| `node probe.mjs` | Диагностика API, сверка с документом |
| `node --test test/all.test.mjs` | Тесты |

На сервере запускать `sync.mjs` раз в 10 минут (cron / планировщик задач). Остатки в 1С обновляются с той же частотой.
Объём каталога ~3 тыс. позиций, это 3–4 страницы на endpoint, поэтому выгрузка всегда полная, без `updated_since`.
Фото качаются, только если поменялся `image_updated_at`.

Если запрос упал, старый `catalog.json` остаётся на месте и сайт показывает последний удачный снимок. Код выхода 1.

## Правила из документа, которые здесь реализованы

- Цена = `price_per_gram` группы × `avg_weight`, округление до 2 знаков, половина вверх (целочисленно, без ошибок float).
- `is_active = false` → товар скрыт. `price_per_gram = 0` → товар скрыт (продавать нельзя).
- Товары без остатка остаются в каталоге с `inStock: false`.
- Размер берётся из `sku` (артикул + «-» + размер через точку), остаток — по каждому размеру из `/stock`.
  `size_min/size_max` из `/products` не используются: они считаются на момент запроса и могут не совпасть с `/stock`.
- 401 без тела → неверный логин/пароль, 401 с JSON → неверный токен. 500/503 → 3 повтора с паузой.
- Не чаще 1 запроса в секунду (лимит API — 60 в минуту).
- Остатки можно брать с отдельной публикации (`STOCK_URL`). Адрес `stockapi` (10.10.10.19) снаружи недоступен, поэтому сейчас остатки берутся из `/stock` каталога.
- Товары с `avg_weight = 0` скрыты: цена получается 0.
- Название «181001926 Кольцо (585,5)» очищается до «Кольцо», а на сайте к нему добавляется артикул.

## Формат товара в catalog.json

```json
{
  "id": "GUID номенклатуры", "article": "SZ-R-01245", "name": "Кольцо из белого золота с бриллиантом",
  "cat": "rings", "metal": "white", "probe": 585, "w": 2.915,
  "price": 2769250, "price_per_gram": 950000, "currency": "UZS",
  "sizes": [{ "value": "17.0", "stock": 2, "sku": "SZ-R-01245-17.0", "size_id": "GUID" }],
  "stock": 4, "inStock": true, "set_id": "GUID комплекта или null",
  "isNew": true, "isBestseller": false, "image": "data/img/<id>.jpg"
}
```

`cat` и `metal` — коды, как в `frontend/assets/js/core.js`. Соответствие текстов 1С
(`product_type`, `color`) задаётся таблицами в `lib/transform.mjs`. Неизвестные значения попадают в `warnings`
каталога, сборку они не ломают. Таблицы надо дополнить, когда 1С пришлёт полный список значений.
