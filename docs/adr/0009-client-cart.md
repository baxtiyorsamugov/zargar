# ADR-0009: Корзина хранится в браузере, цены проверяет сервер

- **Статус:** Принято
- **Дата:** 2026-11-10

## Контекст

Корзина нужна и гостям, и зарегистрированным покупателям. Витрина — Next.js со статическими (ISR) страницами, API — Django. Цены и остатки приходят из 1С и могут измениться, пока товар лежит в корзине.

## Решение

- В браузере (localStorage) хранятся только `variant_id` и количество. Ни цен, ни названий.
- Страница корзины запрашивает `POST /api/v1/cart/`. Сервер возвращает актуальные названия, цены, наличие и итог.
- При оформлении `POST /api/v1/orders/` сервер **заново** проверяет варианты, активность товара и остатки. Цены берутся только из БД. Цене, присланной клиентом, сервер не доверяет.

## Альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| Корзина в БД по сессии | Видна менеджеру, работает между устройствами | Таблица мусорных корзин гостей, каждое «добавить» — запрос к API |
| **localStorage + проверка на сервере** ✅ | Мгновенно, без нагрузки на API, страницы остаются статическими | Корзина не переносится между устройствами |

## Последствия

- Брошенные корзины менеджеры не видят. Если понадобится (напоминания, аналитика), корзину залогиненного пользователя можно синхронизировать с сервером отдельной задачей.
- Остатки при заказе не списываются: источник истины по остаткам — 1С (этап 04). Сайт только не даёт заказать больше, чем есть.
