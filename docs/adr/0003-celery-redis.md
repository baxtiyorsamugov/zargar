# ADR-0003: Celery + Redis для фоновых задач и интеграций

- **Статус:** Принято
- **Дата:** 2026-11-10

## Контекст

Обмен с 1С, отправка в Bitrix24 и уведомления не должны выполняться внутри HTTP-запроса покупателя: внешняя система может отвечать медленно или быть недоступна. Нужны расписание, повторы и очередь.

## Решение

Celery (worker + beat) с брокером Redis. Все вызовы внешних систем — только через задачи Celery с повторами и экспоненциальной задержкой.

## Альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| cron + management commands | Просто | Нет очереди, повторов, параллелизма |
| Dramatiq / RQ | Проще Celery | Меньше экосистема, нет встроенного расписания (RQ) |
| **Celery + Redis** ✅ | Стандарт для Django, расписание (beat), повторы | Ещё два процесса в инфраструктуре |

## Последствия

- Каждая задача интеграции должна быть **идемпотентной** — повтор не создаёт дублей.
- Redis заодно используется как кэш.
